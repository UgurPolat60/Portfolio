Desktop Game · University Final Project

Tower Defense (Java)

A tower defense game written from an empty file in Java, without touching a game engine of any kind.

  • Java
  • Swing (JFrame / JPanel)
  • AWT — Graphics2D
  • BufferedImage & sprite slicing
  • Object-oriented design
  • Inheritance & polymorphism
  • Multithreading
  • Event-driven input
  • File I/O save & load

Built during my computer engineering degree at Bolu Abant İzzet Baysal University, without touching Unity, Godot or any other ready-made engine — only Java and Swing. From the sprite engine that draws the map to the AI that runs the enemy waves, every line came from me.

A scene-based state machine

Menu, Playing, Game Over and Edit (the map editor) are separate scenes, and transitions between them run through a shared scene interface. Each scene owns its own update and draw loop; the common flow is managed from a single place. This is the structure most tutorials skip and most projects later regret skipping.

Two threads, one consistent rhythm

Game logic updates and screen rendering run at different rhythms and are synchronised to hold a consistent frame rate. This was the first project where I solved a real multithreading problem end to end in something someone else would actually run.

Responsibilities split into manager layers

WaveManager, EnemyManager, TowerManager, ProjectileManager and MapManager — every responsibility lives in its own class. Enemy types such as Orc and Bat derive from a shared Enemy base, so adding a new enemy means writing one subclass and nothing else.

My own map editor

I wrote a tile-based editor: start and end points and the path are laid down freely, saved to disk in my own file format, and loaded back through a save/load class. The map in these screenshots was designed with it. Building the tool was faster than placing tiles by hand twice.
